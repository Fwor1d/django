## Изменения, сделанные по результатам аудита

### ПЗ №3–5. Указана группа

В подвал `blog/templates/blog/base.html` добавлена группа **ДЭ 23-24** наряду с именем автора и направлением. Это устраняет формальную недостачу, когда был указан только автор и направление.

### ПЗ №6. Дополнительное поле в admin

Модель `Post` уже содержала `summary`, и краткое описание уже выводилось в карточках. Теперь `summary` также добавлено в `list_display` административной панели.

### ПЗ №8. Отдельный шаблон редактирования

Методичка указывает `post_form_edit.html`. Ранее применялся один `post_form.html` для создания и редактирования. Добавлен `blog/templates/blog/post_form_edit.html`, который наследует общий шаблон формы без дублирования разметки; `post_edit` использует отдельный путь к шаблону.

### ПЗ №10. Устойчивый порядок пагинации

Перед `Paginator(posts, 5)` в `blog/views.py` добавлено `posts.order_by("-created_at", "-pk")`. Ранее функциональные тесты проходили, но в логе был `UnorderedObjectListWarning`. Эта явная сортировка делает порядок детерминированным.

### ПЗ №15. Маршрутизация и настройки

В `blog/urls.py` теперь определены маршруты `/`, `/about/` и пути `/blog/`. Корневой `mysite/urls.py` подключает все маршруты через `path("", include("blog.urls"))`. Шаблон меню и тесты используют `blog:home`, `blog:about`; остальные пути уже использовали `blog:*`. В `mysite/settings.py` добавлены доверенные HTTPS-источники CSRF из методички. Ранее уже были реализованы slug, дата публикации в адресе, `get_absolute_url()`, `get_edit_url()`, `get_delete_url()` и canonical HTML-тег.

## Особенности, которые следует оговорить преподавателю

1. **ПЗ №7**: `/blog/<pk>/` не отображает отдельную страницу напрямую — выполняет постоянное перенаправление на канонический URL из ПЗ №15. Это осознанное изменение итоговой версии.
2. **ПЗ №11**: регистрация перенесена в `accounts/views.py` на этапе ПЗ №12, поэтому её нет в `blog/views.py`.
3. **ПЗ №8**: шаблон редактирования существует, но наследует общую форму; это уменьшает дублирование.
4. **ПЗ №15**: поле `slug` содержит одновременно `unique=True` и `unique_for_date='created_at'`. Уникальность на уровне базы глобальная и строже, чем проверка уникальности в пределах даты; это допустимо для учебного блога.
5. **ПЗ №5**: FAQ специально оставлен ссылкой-заглушкой согласно индивидуальному заданию.
6. **Отчёты**: текущие README и ответы — текстовая основа; если преподаватель требует именно отдельный документ для каждой практической, необходимо предоставить файлы в требуемом формате. Скриншоты пользователь планирует показывать на занятии.

## Проверка после изменений

До аудита на MacBook были зафиксированы:

```text
Found 16 test(s).
System check identified no issues (0 silenced).
Ran 16 tests in 1.599s
OK
```

Это результаты **до последних исправлений в GitHub**, поэтому нельзя утверждать, что уже проведён повторный прогон именно нового коммита. Повторная проверка после `git pull`:

```bash
cd ~/django_practice/mysite
source ../.venv/bin/activate
git pull --ff-only
python manage.py check
python manage.py test blog accounts
python manage.py runserver
```

После запуска нужно открыть `/`, `/about/`, `/blog/`, один пост и `/admin/`, проверить меню, вход и форму создания. В ходе повторной проверки предупреждение `UnorderedObjectListWarning` больше не должно появляться.
