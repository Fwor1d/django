## Выполнение задания: Поиск и пагинация

**Цель:** реализовать фильтрацию QuerySet и разбиение результатов на страницы.

**Выполнено.** Добавлена GET-форма поиска с параметром `q`. Запрос ищет совпадения по заголовку, тексту и краткому описанию посредством `Q` и `icontains`. Для списка используется `Paginator(posts, 5)`. В ссылках перехода между страницами сохраняется поисковая строка. Для некорректных номеров страниц используется `get_page`, который не приводит к необработанному исключению.

**Основные файлы:** `blog/views.py`, `post_list.html`.

**Пример фильтрации:**

```python
posts.filter(
    Q(title__icontains=query)
    | Q(body__icontains=query)
    | Q(summary__icontains=query)
)
```

**Теоретические выводы.** Оператор `|` между объектами `Q` означает логическое «ИЛИ». `icontains` выполняет поиск подстроки без учёта регистра. QuerySet представляет полный запрос к БД, а `Page` — только выбранную часть результатов вместе с информацией о предыдущей и следующей страницах. Сохранение параметра `q` важно, чтобы поиск не сбрасывался при перелистывании.

**Результат:** публикации выводятся по пять на страницу, одновременно работают поиск и пагинация. Для демонстрации добавлена команда `seed_blog_demo`, создающая 12 учебных постов без повторного добавления уже существующих.

**Замечание:** ранее встречалось предупреждение `UnorderedObjectListWarning`. Теперь перед созданием `Paginator` QuerySet явно сортируется по `-created_at` и `-pk`; после этой правки требуется повторный запуск тестов.

**Материалы для отчёта:** список, поисковый результат, переключение страниц с сохранённым запросом.

## Контрольные вопросы и ответы: Поиск и пагинация

**1. Что делает Q(title__icontains=query) | Q(body__icontains=query), и чем отличается от filter(title__icontains=query)?**

Оператор `|` объединяет два условия логическим «ИЛИ», поэтому пост будет найден по совпадению либо в заголовке, либо в тексте. Простой `filter(title__icontains=query)` учитывает только заголовок. В проекте поиск дополнительно охватывает краткое описание `summary`.

**2. В чём разница между posts_qs (QuerySet) и page_obj? Что находится в page_obj.object_list?**

QuerySet описывает полную выборку подходящих записей и позволяет продолжать фильтрацию и сортировку. `page_obj` представляет только одну страницу результатов и содержит номер страницы, признаки наличия соседних страниц и ссылки на paginator. `page_obj.object_list` — объекты, попавшие на текущую страницу.

**3. Как работает Paginator и чем get_page удобнее ручной обработки PageNotAnInteger/EmptyPage?**

`Paginator(queryset, 5)` разбивает записи на страницы по пять элементов. `get_page(number)` возвращает подходящую страницу и обрабатывает ошибочный номер, в том числе слишком большой или нечисловой. Это избавляет от явного `try/except` для `PageNotAnInteger` и `EmptyPage` в типовом сценарии.

**4. Почему важно сохранять q в ссылках пагинации?**

При поиске пользователь ожидает перелистывать только найденные результаты, а не весь блог. Если не включить `q` в ссылки «Назад», «Далее» и номера страниц, поисковое условие пропадёт при следующем запросе. В проекте для этого формируется `query_parameter`.
